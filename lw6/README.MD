Ось відповіді на наступну частину ваших контрольних запитань. Матеріал охоплює як теорію Bluetooth, так і специфіку роботи з периферією STM32.

---

### 1. Архітектура мереж Bluetooth

Bluetooth базується на топології Piconet (пікомережа).

* Piconet: Об'єднання одного ведучого пристрою (Master) та до 7 активних ведених (Slave). Всі пристрої в пікомережі синхронізуються за годинником та частотною послідовністю Master.
* Scatternet: Кілька пікомереж, що перекриваються. Один пристрій може бути Slave в обох мережах або Master в одній і Slave в іншій, забезпечуючи передачу даних між мережами.

### 2. Стек протоколів Bluetooth

Стек поділяється на три рівні:

1. Transport Layer: Радіочастотний (Physical), Baseband, Link Manager (LMP).
2. Middleware Layer: L2CAP (логічне керування), RFCOMM (емуляція COM-порту), SDP (пошук сервісів).
3. Application Layer: Профілі (Profiles), які визначають конкретні функції.

### 3. Профілі Bluetooth

Профіль — це набір специфікацій, що визначають, як пристрій реалізує певну послугу.

* SPP (Serial Port Profile): Емуляція послідовного порту (як у вашому HC-05).
* HFP/HSP: Для гарнітур та дзвінків.
* A2DP: Передача якісного стереозвуку.

### 4. Фізичні особливості радіоканалу

* Працює в безліцензійному діапазоні ISM 2.4 ГГц.
* Діапазон розділений на 79 каналів (для Classic) або 40 каналів (для BLE) з кроком у 1 або 2 МГц відповідно.
* Використовує методи модуляції GFSK, $\pi/4$-DQPSK або 8DPSK.

### 5. Стрибкоподібна зміна частоти (FHSS)

FHSS (Frequency Hopping Spread Spectrum) потрібна для:

1. Завадостійкості: Якщо один канал зайнятий (наприклад, Wi-Fi), наступний пакет піде на іншій частоті.
2. Безпеки: Складніше перехопити сигнал, не знаючи алгоритму зміни частот (1600 стрибків за секунду).

### 6. Типи з’єднань Bluetooth

* SCO (Synchronous Connection-Oriented): Для голосу. Резервує смугу пропускання, дані не пересилаються повторно при помилках (важлива реальність часу, а не точність).
* ACL (Asynchronous Connection-Less): Для даних. Пакетна передача, підтримує повторне відправлення при помилках (ARQ).

### 7. Рівень L2CAP

Logical Link Control and Adaptation Protocol виконує:

* Мультиплексування даних від різних протоколів вищого рівня.
* Сегментацію (розбиття великих пакетів на дрібні кадрів) та збирання.
* Управління якістю обслуговування (QoS).

### 8. Структура кадрів Bluetooth

Типовий пакет складається з 3 частин:

1. Access Code (72 біти): Для синхронізації та ідентифікації пікомережі.
2. Header (54 біти): Адреса Slave, тип пакета, контроль потоку, чексума (HEC).
3. Payload (0–2745 бітів): Самі дані.

### 9. Формати кадрів для різних швидкостей (EDR)

В режимі EDR (Enhanced Data Rate) службові частини (Access Code та Header) передаються на базовій швидкості (1 Мбіт/с з GFSK), а Payload — на підвищеній (2-3 Мбіт/с з DQPSK/8DPSK). Це забезпечує сумісність зі старими пристроями.

### 10. Модуль HC-05

Це популярний Bluetooth-UART модуль.

* Особливість: Підтримує два режими — Data Mode (передача даних) та AT Mode (налаштування через команди).
* Має вивід Key/EN для переходу в режим налаштування. Працює на рівні профілю SPP.

### 11. RTC в STM32

Real Time Clock (RTC) — це незалежний BCD-лічильник (Binary-Coded Decimal).

* Особливості: Працює навіть у режимах глибокого сну (Standby/Stop), якщо є живлення на виводі $V_{BAT}$. Має власну систему календарних даних (час, дата, підкачка високосних років).

### 12. Налаштування RTC в STM32

1. Увімкнути тактування модуля (зазвичай через шину APB1).
2. Увімкнути доступ до Backup-домену (`PWR_CR_DBP`).
3. Вибрати джерело тактування (LSE, LSI або HSE/128).
4. Налаштувати дільники (Prescalers) для отримання частоти 1 Гц.

### 13. Інтерфейс для HC-05

Модуль HC-05 підключається до STM32 через UART/USART.

* Вибір: Швидкість (Baudrate) має збігатися з налаштуваннями модуля (дефолт 9600 або 38400 для AT). Довжина слова 8 біт, 1 стоп-біт, без контролю парності.

### 14. Структури у мові С

Структура (`struct`) дозволяє об'єднати змінні різних типів під одним ім'ям.

* Використання: Опис об'єктів (наприклад, структура `Student` з ім'ям та балами) або групування налаштувань периферії (як `UART_HandleTypeDef` в HAL).

### 15. strcpy vs strcat

* `strcpy(dest, src)`: Повністю копіює рядок `src` у `dest`, затираючи те, що було в `dest`.
* `strcat(dest, src)`: Додає (конкатенує) рядок `src` в кінець рядка `dest`.

### 16. Колбеки (Callbacks) в STM32 HAL

Колбеки — це механізм "зворотного виклику".

* Навіщо: HAL-бібліотека сама обробляє низькорівневе переривання (очищення прапорів тощо), а потім викликає "порожню" функцію-колбек (наприклад, `HAL_UART_RxCpltCallback`). Розробник просто перевизначає цей колбек у своєму коді, не втручаючись у системні файли преривань.

### 17. Чому 32,768 кГц?

Це значення дорівнює точно $2^{15}$ Гц.

* Обґрунтування: Для отримання імпульсу частотою 1 Гц (що дорівнює 1 секунді) мікроконтролеру достатньо використати простий 15-бітний двійковий дільник. Коли лічильник переповнюється, проходить рівно одна секунда. Це апаратно просто і дуже енергоефективно.
